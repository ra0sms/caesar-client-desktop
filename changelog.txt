CAESAR Desktop - Changelog
==========================

v1.2.4 (2026-10-24)
-------------------
- Add: voice keyer has six message slots (F1-F6) in a compact 2 x 3 grid: name, send,
  small Listen (▶) and Record (●) buttons and the message length
- Add: recording over an existing message asks for confirmation
- Add: Folder button opens the message folder (~/.caesar-desktop/voice); slots are
  re-read when the window becomes active, so WAV files dropped there appear at once.
  README describes the folder and which WAV files can be used
- Fix: GStreamer errors shown in the window could be a library info line such as
  "libva info: VA-API version ..." instead of the actual error

v1.2.3 (2026-10-19)
-------------------
- Add: voice keyer (Linux) — three message slots with a name, Rec, Listen and Send.
  Rec records up to 30 s from the selected input (~/.caesar-desktop/voice/msgN.wav),
  Listen plays it to the local output, Send (F1-F3) keys PTT and sends the message
  through the same audio stream as the mic, then releases PTT 300 ms after the end.
  Esc, the same F-key or the PTT button stop it; manual PTT (button or pedal) takes
  over from a message without unkeying the radio
- Fix: since v1.2.2 every later gst-launch-1.0 recording on the system (other apps
  too) started muted: the sound server remembers mute per application name and the
  muted TX stream shared that name. The TX stream is now named "caesar-tx".
  If recordings are still silent after updating, unmute "gst-launch-1.0" once in the
  sound settings (e.g. pavucontrol, Recording tab)
- Fix: connecting no longer overwrites the whole config file (it would drop settings
  such as the voice keyer message names)

v1.2.2 (2026-10-18)
-------------------
- Add: the microphone is muted while not transmitting (Linux). The server plays all
  TX audio into the radio, so room noise reached it all the time and could key it
  via VOX. Only the client's own PulseAudio capture stream is muted (other apps keep
  the mic); PTT on (button or pedal) opens it within ~10-20 ms without delaying the
  PTT packet. If the stream can't be found the mic stays open and a warning is shown
- Fix: an empty input/output device no longer breaks the audio pipeline; the system
  default device is used

v1.2.1 (2026-10-17)
-------------------
- Fix: PTT keepalive could race with PTT release and send a '1' after the OFF packet,
  keying the transmitter again for up to 0.5 s (until the server's keepalive timeout)
- Fix: CAT virtual port (PTY) was never switched to raw mode (the setup error was
  swallowed): until the CAT program reconfigured the port, radio replies were echoed
  back to the radio, held back until a newline, and CI-V bytes 0x0D/0x03/0x7F mangled
- Fix: CAT bridge reconnects when the server closes the connection (IP not allowed,
  web panel restart) instead of showing ONLINE with a dead link; commands typed while
  offline are discarded rather than replayed to the radio; a PTY nobody reads can no
  longer hang the bridge
- Add: "NOT ALLOWED" status with the IP the server sees when this machine's IP is not
  in the server's client_ip.cfg (nano-server with PING_UNAUTHORIZED reply)
- Add: GStreamer pipeline failures (bad device, missing plugin, busy port, device
  unplugged) are shown under the status line; full gst-launch output on the console
- Add: only one client can run at a time (lock file + UDP 5000/5002 check, also
  catches older versions); a second start shows a message instead of failing silently
- Add: Opus packet loss concealment on RX (smoother audio over VPN / mobile links)
- Fix: config is saved atomically and missing keys fall back to defaults
- Deps: removed unused psutil; sounddevice only on macOS; PyInstaller moved to
  requirements-dev.txt
- Quality: removed unused PulseAudio loopback helpers; unit tests in tests/
  (python -m unittest discover -s tests -t .)

v1.2.0 (2026-09-23)
-------------------
- Add: automatic CW (Morse code) decoder based on the DeepCW neural model
  (morse/deepcw/, run with onnxruntime) — decodes reliably on weak signals,
  in heavy noise and through QSB
- Add: decoded text appears character by character (~1 s after each character)
  in a live one-line scrolling ticker, with a separator between transmissions
- Add: automatic beat-tone detection (300–1250 Hz; tones outside the model's
  400–1200 Hz band are frequency-shifted into it) and automatic WPM estimate
- Add: RX audio tap branch (tee + fdsink) in audio/rx.py — decoded PCM is branched off
  to the CW decoder without touching the playback path or the network stream
- Add: CW Decoder panel in MainWindow (enable checkbox, detected tone display,
  WPM estimate, Clear) and gui/marquee.py — single-line scrolling ticker ("бегущая строка")
- Add: morse_enabled setting persisted to config
- Add: offline self-test (python -m morse.self_test) that sweeps tones/WPM/noise
- Add: optional diagnostic trace for the decoder (CAESAR_MORSE_DEBUG=<path>,
  also dumps the raw decoder input audio)
- Perf: neural inference runs in its own thread; the RX reader thread only buffers audio
- Fix: CAT virtual serial port (PTY) is now owner-only (0600) instead of world-writable
- Deps: added numpy and onnxruntime; build scripts bundle the model and onnxruntime
- License: the DeepCW model is AGPL-3.0 (see morse/deepcw/LICENSE and README.md)
- Quality: added .gitignore; remaining comments and docstrings translated to English
